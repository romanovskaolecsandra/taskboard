## Крок 5. Дослідження у DevTools

### 5.1 Таблиця Network

| Запит (Name) | Метод | Статус | Тип | Розмір |
| :--- | :--- | :--- | :--- | :--- |
| `127.0.0.1` | GET | 200 / 304 | document | ~2.3 KB |
| `logo.png` | GET | 200 / 304 | png | ~243 B |

* **Request URL:** http://127.0.0
* **Request Method:** GET
* **Status Code:** 200 OK (або 304 Not Modified)
* **Content-Type:** text/html; charset=utf-8

### 5.4 Робота з Console
* **Що повернула перша команда `document.title`?**  
  Вона повернула текстове значення заголовка вкладки: `"TaskBoard"`.
* **Що зробила друга команда `document.body.style.background = "lightyellow"`?**  
  Вона динамічно змінила колір тла сторінки в браузері на світло-жовтий.
* **Збережеться це після F5?**  
  Ні, після перезавантаження сторінки зміни зникають, оскільки оригінальний файл на диску не змінювався.

## Крок 6. Відповіді на запитання

1. **Яка адреса сторінки в браузері? З яких частин вона складається?**  
   Адреса сторінки — `http://127.0.0`. Вона складається з протоколу (`http://`), IP-адреси локального комп'ютера (`127.0.0.1`), номера порту розширення Live Server (`5500`) та шляху до файлу сторінки (`/index.html`).

2. **Скільки запитів зробив браузер при завантаженні сторінки і чому саме стільки?**  
   Браузер зробив 2 основні запити. Перший запит завантажує структуру сайту з файлу `index.html`. Коли браузер аналізує цей код і бачить тег `<img>`, він автоматично надсилає другий окремий запит для завантаження файлу зображення `logo.png`.

3. **Що відбулось, коли ти поставив неправильний шлях до зображення?**  
   На сторінці замість картинки відобразився альтернативний текст з атрибута `alt`. У вкладці DevTools Network цей запит підсвітився червоним кольором і отримав статус помилки `404 Not Found`.

4. **Чому зміни, зроблені через DevTools, зникли після F5?**  
   Інструменти DevTools дозволяють змінювати сторінку лише в режимі реального часу в оперативній пам'яті самого браузера. При натисканні F5 сторінка завантажується заново з оригінальних файлів проекту на диску, які залишилися незмінними.

5. **Хто в цій схемі клієнт, а хто сервер?**  
   Клієнтом виступає веб-браузер, який робить запити. Сервером є розширення Live Server у Visual Studio Code, яке очікує на запити і видає файли проекту з локального комп'ютера.
